Implemented behavior change: `src/client/handlers/user_state.rs` no longer treats pre-auth `UserState` as a protocol violation. Before authentication it applies only `self_mute` and `self_deaf` to the sender's global state, using the same implicit rules as authenticated self updates (`self_deaf=true` implies `self_mute=true`, `self_mute=false` clears self-deaf). Other pre-auth `UserState` fields are ignored. Added `TestClient::connect_with_preauth_messages` and integration test `pre_auth_user_state_only_updates_self_mute_deaf` in `src/integration_tests/scenarios/self_actions.rs`.
