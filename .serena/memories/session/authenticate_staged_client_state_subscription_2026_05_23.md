Implemented native authenticate/client-state subscription handoff: `ClientRepository::snapshot_with_versions_and_subscription_in_server` subscribes to the client-state broadcast channel while holding the client register read lock and returns the server-scoped client snapshot plus version vector. `handle_authenticate` now takes that subscribed snapshot immediately before building the initial auth burst/UserState list, stages the receiver on `Client`, and updates last-seen versions from the same snapshot. `activate_client_subscriptions` consumes the staged receiver instead of opening a fresh one, then publishes the client and replays from last-seen; the live client-log loop now ignores stale broadcasts whose entry version is already <= last_seen to avoid replay/queued duplicate delivery. Added focused unit test `subscribed_snapshot_receives_followup_client_state_entries`.
